# 从 Tabletop 到 Humanoid：世界动作模型（WAM）研究提案

**日期**：2026-07-29
**背景文档**：《具身世界模型文献调研_2026-07.md》

---

## 0. 先回答问题：现有相关工作有哪些

**结论：不是空白，但也远未成熟。** 语料中直接做"humanoid WAM"的工作有两篇,是很好的起点,但都还没有解决 humanoid 特有的核心难题。

### 0.1 直接相关：Humanoid WAM

**MotionWAM**（2606.09215，本次调研已收录）
现有 humanoid WAM 里最直接的一篇。做法:策略条件于**视频世界模型的中间去噪特征**,而非完整生成视频。核心贡献是打破"上身操作策略 + 下身平衡控制器"的传统层级分割,提出**统一运动 latent**,把移动、躯干运动、身高调节、脚部交互、手部操作放进单一动作空间联合预测。在 Unitree G1 上 9 个真实任务,整体成功率超同等演示数据微调的 VLA 基线 30%+,并能完成上下身解耦策略无法做到的任务驱动脚部交互。**局限**:仍是单机型(G1),未讨论跨具身;论文未明确讨论 latent 表征的物理可解释性;实时性达标但训练数据规模有限。

**Being-M0.7**（BeingBeyond team,2026-07-14,本次新纳入语料）
比 MotionWAM 更接近你想问的方向——它是一个**显式的 latent World-Action Model for Humanoid Robots**。核心设计:
- 在**混合模态、人类中心语料**(egocentric 视频 + 人类动作捕捉)上预训练一个"video-motion prior",不 rollout 像素,而是在 latent 空间预测未来状态,并与未来动作耦合进一个**人类与人形机器人共享的紧凑全身表征**
- 用 **Mixture of Transformers (MoT)** 结构,多模态输入(图像 latent、动作、指令)共享注意力、各自 FFN
- 机器人后训练阶段,用一个轻量 action expert,把预训练的 video-motion prior 用**有限的人形演示数据**接地为可执行全身指令
- 在 Unitree G1 上验证了状态预测、动作生成、人形移动、灵巧操作的协调能力

这篇论文的价值在于:它是"人类视频/动作数据 → 人形机器人全身控制"这条数据路径上,目前语料里**唯一明确验证了 latent WAM 可行性**的工作。但论文仍处于早期阶段(单一 G1 平台、任务范围有限、未系统评测跨任务泛化)。

### 0.2 紧密相关但非 WAM 本身：Humanoid 基础设施

这些不是 WAM,但决定了你搭 humanoid-WAM 实验时绕不开的基础设施问题:

- **HEX**（2604.07993）:针对"多数 VLA 把机器人各部位当独立整体处理,导致高自由度人形控制不稳定"的问题,提出**以状态为中心**的框架,引入人形对齐的通用状态表征支持跨异构具身的可扩展学习,并用 Mixture-of-Experts 统一策略处理协调操作。这直接命中你要搭 humanoid-WAM 时会遇到的"动作空间统一"问题。
- **SIMPLE**（2606.08278,USC PSI Lab)：**这是你最该关注的一篇**。它是专为标准化人形基础模型评测与训练设计的仿真基准——60 个全身任务、50 个室内场景、1000+ 物体资产,融合 MuJoCo 的接触物理与 Isaac Sim 的真实感渲染,**原生支持对 SOTA VLA 与 WAM 的评测(论文明确列出 π0.5、DreamZero 等)**。换句话说,评测基础设施已经有人在建,你不需要从零造轮子。
- **Scaling Behavior Foundation Model for Humanoid Robots**（2607.15163）：覆盖灵巧操作、自然敏捷移动、全身协调 loco-manipulation 的行为基础模型,是"通用人形控制"路线的代表,可作为你的策略侧基线或对照组。
- **FALCON**（2505.06776）、**HEFT**（2607.02332）、**Kinematics-Aware Multi-Policy RL**（2511.21169）:这几篇聚焦**力感知**的全身 loco-manipulation(负重搬运、开门、推车等),提醒你一个 tabletop WAM 完全不需要考虑的维度——**力/接触在全身尺度上与平衡强耦合**,这是 tabletop 操作里没有的物理复杂度。

### 0.3 你提到的 GR00T / Sonic 这类通用 humanoid-VLA

这些是**反应式策略**路线(直接 `p(a|o,l)`),不显式建模世界演化,和 WAM 是正交的两条线。目前语料里没有看到"把 GR00T/Sonic 这类通用 humanoid-VLA 接上显式世界模型"的工作——**这恰恰是空白所在**,也是下面提案要填的坑。

### 0.4 一句话结论

**Tabletop → Humanoid 的 WAM 化,目前只有 MotionWAM(中间特征条件)和 Being-M0.7(latent 世界-动作联合预训练)两个先行者,都还停留在单一具身、任务范围有限的早期阶段。跨具身泛化、力/接触建模、evaluation 生态(部分由 SIMPLE 打底)、以及"世界模型是否真的比强化学习/模仿学习基线在 humanoid 上更值"这几个问题,都还没有定论。这是一个窗口期,不是红海。**

## 1. 研究提案

### 1.1 立项动机

Tabletop WAM 已经把"世界建模是否对操作策略有用"这个问题基本论证清楚(本调研 §8 的六条优势)。但 humanoid 场景在三个维度上跟 tabletop 有本质差异,现有 tabletop 的结论**不能简单外推**:

1. **动作空间维度与耦合方式完全不同**。Tabletop 是 6-7 DoF 臂 + 夹爪,动作近似解耦、低维、慢速。Humanoid 是 20-40+ DoF 全身,上肢操作与下肢平衡**强耦合**——手臂伸出去的重心偏移必须由腿部实时补偿,这是 tabletop 里不存在的动力学约束。MotionWAM 论文明确点出这一点:传统的"上身策略 + 下身平衡控制器"层级分割,会把腿部降格为纯粹的平衡维持,牺牲了任务驱动的脚部交互能力。
2. **控制频率的下限被平衡稳定性而非任务精度决定**。Tabletop 操作的控制频率(如 π0.5 的 50Hz)是由抓取精度需求决定的;humanoid 的下肢平衡回路往往需要 200Hz+ 甚至更高的关节力矩闭环,而生成式世界模型的推理延迟(哪怕是本调研里最快的 GigaWorld-Policy-0.5 的 85ms,约 12Hz)**离这个下限差两个数量级**。这不是"再优化一下"能解决的差距,是根本性的架构问题。
3. **自我运动(ego-motion)与环境变化的纠缠更严重**。EgoWAM 的核心论点是"有效的世界目标应当把相机运动与环境变化分离"——tabletop 场景相机通常固定或缓慢移动,这个分离相对容易。Humanoid 的头戴相机会随着**步态、转身、蹲下**产生大幅度、周期性、与任务无关的运动,这个"噪声"比 tabletop 场景大一个量级,如果处理不好,世界模型会把步态节律错误地编码进"世界如何演化"里。

### 1.2 核心研究问题(按优先级)

**RQ1(表征选型,最高优先级)**:对 humanoid 而言,哪种世界表征最有效——像素(MotionWAM 式中间特征)、纯视觉 latent(Being-M0.7 式)、显式全身运动状态(关节角度/末端位姿构成的低维状态)、还是三者的某种融合?这本质上是把 EgoWAM 的"受控消融"方法论(固定策略骨干、只换世界预测目标)搬到 humanoid 场景重做一遍——**因为 EgoWAM 的结论是在 tabletop 双臂任务上得出的,尚未在全身控制上验证过**。

**RQ2(动作空间统一)**:上肢操作动作(连续、任务导向)与下肢移动动作(周期性、平衡导向)是否应该在同一个 latent 动作空间里联合建模?还是需要 HEX 式的 Mixture-of-Experts 显式解耦、再通过共享状态表征协调?MotionWAM 选择了统一空间并证明了收益,但没有做对照消融(统一 vs 解耦)。

**RQ3(实时性下限)**:下游全身控制到底需要多高频率的世界模型输出?WAM 综述提出的"task-adaptive predictive fidelity"在 humanoid 场景应该如何具体化——是否可以让世界模型只对**手臂/操作相关的子空间**做高保真、低频预测,而下肢平衡完全交给一个独立的高频反应式控制器,世界模型只提供"意图"层面的调制信号?

**RQ4(接触与力)**:tabletop 的物理一致性研究(PhysisForcing)聚焦手-物体接触;humanoid 全身尺度上,脚-地面接触直接决定能不能站稳,这是安全关键的。世界模型的接触预测误差在这里的后果比 tabletop 严重得多(参考 FALCON、HEFT 对力交互的重视)。世界模型要不要显式预测接触力/地面反作用力,而不只是视觉状态?

**RQ5(数据)**:humanoid 全身遥操作数据比 tabletop 臂式遥操作**贵得多、危险得多**(涉及摔倒风险)。人类第一视角视频 + 动作捕捉(Being-M0.7 的路径)能在多大程度上替代真机全身演示?这本质是把 HumanScale(第一视角视频超越真机数据)的结论从 tabletop 操作外推到全身运动,是否依然成立?

### 1.3 技术方案

**总体架构选择:latent WAM,而非像素 WAM。** 理由直接来自本调研的证据链——EgoWAM 的受控消融、2605.06388 的编码器对照、以及 humanoid 场景本身对实时性的严苛要求,三条证据都指向像素级重建在这个场景性价比最低。Being-M0.7 已经验证了这个方向可行,应作为架构起点而非从零设计。

**第一阶段:表征选型实验(对应 RQ1)**

参照 EgoWAM 的方法论搭建对照实验:固定策略骨干(建议直接用 HEX 或 Scaling BFM 的开源全身策略骨干)、固定动作头、固定数据配比,只切换世界预测目标,至少对比四组:

- Pixel(基线,预期最差)
- 2D 语义 latent(DINOv3/V-JEPA 2.1,复用 tabletop 已验证的最优选)
- 全身运动状态(关节角度序列 + 根节点位姿,类似 μ0 的 3D trace 思路但扩展到全身骨架)
- 融合(视觉 latent + 运动状态联合预测,Being-M0.7 的路线)

评测复用本调研 §9.2 Phase 2 提出的三项诊断(线性可解码性、动作 Jacobian 正确性、多步 rollout 误差累积),额外加一项 humanoid 特有指标:**平衡扰动下的表征稳定性**——对输入施加模拟的推搡/滑倒扰动,看 latent 表征是否能保持对"任务相关状态"的解码能力而不被平衡恢复动作污染。

**第二阶段:动作空间设计(对应 RQ2)**

做两个变体的对照:(a) MotionWAM 式统一 latent 动作空间;(b) HEX 式 MoE 解耦、状态层协调。评测维度:任务成功率、跨任务动作空间迁移能力(在 A 任务训练的下肢控制器能否复用到 B 任务)、以及计算效率(MoE 理论上应该更高效,但协调开销可能抵消这个优势)。

**第三阶段:分层实时架构(对应 RQ3)**

这是我认为**最有工程价值也最容易出成果**的一块。设计思路:

- 高频层(200Hz+):纯反应式全身平衡控制器,不经过生成式世界模型,直接用传统 WBC(whole-body control)或轻量策略网络
- 中频层(10-20Hz):latent WAM 提供"任务意图"层面的调制信号(类似 MotionWAM 的中间特征条件,但目标频率更保守),覆盖操作规划、接触点预测
- 低频层(1-5Hz):高层语义规划(可复用 RxBrain 式的语言推理+视觉想象架构)

这个三层设计直接回应 WAM 综述提出的"Long-Horizon Planning and Temporal Abstraction"开放问题里的"scaling of temporal context"路径,只是把它落到 humanoid 这个具体场景。**关键实验**是验证中频层的调制信号是否真的能提升高频控制器的任务相关性,而不只是增加延迟——这需要做严格的消融(有/无中频调制,同一高频控制器)。

**第四阶段:接触感知世界建模(对应 RQ4)**

把 PhysisForcing 的"物理信息区域定向监督"思路从像素域迁移到全身运动状态域:对脚-地面接触时刻施加额外的监督信号(可以用仿真器里的接触力真值作为训练目标,推理时不需要力传感器)。这是本调研 §9.4 提到的"差异化机会"(多模态 latent 世界模型)在 humanoid 场景的一个具体化,而且 humanoid 天然有仿真器可以提供接触力标注(tabletop 场景往往缺这个)。

**第五阶段:数据配方(对应 RQ5)**

按 Being-M0.7 的路径复现"egocentric 视频 + 动作捕捉 → latent 预训练 → 有限真机数据 grounding",然后做 HumanScale 式的对照:固定预训练数据量,对比"更多第一视角视频 + 更少真机数据"vs"更少第一视角视频 + 更多真机数据"的下游表现,验证第一视角数据在全身运动场景是否依然是高性价比来源,还是说平衡相关的动力学必须从真机数据里学(这是我认为**最不确定**、最值得优先验证的一个假设,因为人类的平衡策略和 humanoid 硬件的重心/惯量分布可能差异很大,不像 tabletop 抓取那样容易跨形态迁移)。

### 1.4 Setup 具体建议

**硬件**:Unitree G1(与 MotionWAM、Being-M0.7 一致,便于直接对比复现结果)作为主平台;如果条件允许,加一台不同构型的人形(如 Unitree H1 或其他全尺寸平台)做跨具身泛化验证,呼应 HEX 的跨异构具身诉求。

**仿真**:直接采用 **SIMPLE** 作为主评测环境——它已经原生支持 VLA 与 WAM 评测,60 任务/50 场景的规模足以支撑表征选型这类需要大量对照实验的研究,不需要自建仿真基准。用 MuJoCo/Isaac Sim 的接触物理做接触力真值标注(对应第四阶段)。

**基线**:
- 反应式策略侧:HEX、Scaling BFM 作为强 VLA/策略基线
- WAM 侧:MotionWAM、Being-M0.7 直接复现或对齐设置作为 WAM 基线
- 力交互侧:FALCON、HEFT 作为高负载/力感知任务的参照(不一定作为直接基线,但其任务设计——负重搬运、开门、推车——值得吸收进评测任务集,因为这些任务恰好是"世界模型需不需要预测接触力"这个问题最有区分度的场景)

**评测指标**:除任务成功率外,建议至少加入:
- 平衡失败率(摔倒/需要人工干预次数)
- 长时程任务的误差累积速率(呼应 tabletop 侧的多步 rollout 诊断)
- 控制频率与端到端延迟(明确报告是否达到平衡回路所需频率下限)
- 跨任务/跨具身迁移成功率

### 1.5 风险与应对

- **最大风险**:humanoid 平衡失败的后果(硬件损坏、安全问题)比 tabletop 抓取失败严重得多,这会限制真机实验的迭代速度。应对:第一、二、三阶段尽量在仿真(SIMPLE)里做完主要消融,只在方案确定后再上真机验证,真机实验设计要包含防摔保护(吊索、软垫)。
- **次大风险**:表征选型实验(RQ1)如果直接照搬 EgoWAM 的三组对照,可能因为 humanoid 数据量远小于 tabletop 而得不出统计显著的结论。应对:优先在仿真里用大规模合成数据把表征选型问题解决,真机数据留给 grounding 阶段(这正是 Being-M0.7 的分工方式)。
- **认知风险**:整个提案的前提是"world model 对 humanoid 有正的边际收益",但本调研 §8.3 指出的核心张力(世界建模的价值在训练梯度还是推理想象)在 humanoid 场景可能完全不同的答案——因为平衡控制对推理延迟极度敏感,"训练时用、推理时不生成"这条路线在这里的吸引力应该比 tabletop 更强。建议把这一点作为第零阶段的一个快速验证:先做一个"世界头训练时用、推理时关掉"vs"完全不用世界建模的纯 VLA"的消融,如果收益很小,及时调整整个研究方向的资源分配。

### 1.6 与本调研已有结论的衔接

这份提案里几乎每一步都在问"tabletop 上验证过的结论,在 humanoid 上还成立吗"——这本身就是提案的核心方法论:**不重新发明问题,而是系统性地重新验证 tabletop 世界模型研究里最重要的几条实证结论(EgoWAM 的目标消融、2605.06388 的编码器对照、WAM 综述提出的训练梯度 vs 推理想象之争),把它们放到全身控制这个动力学耦合更强、实时性要求更高、数据更稀缺的场景里检验。** 如果结论一致,这是对 tabletop 结论泛化性的有力支撑;如果不一致,这本身就是有意思的发现,因为它会告诉我们"世界模型的价值"到底依赖于场景的哪些具体属性(动作维度?控制频率?数据量?),这个问题目前完全没有答案。
